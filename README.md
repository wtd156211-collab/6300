# 时长解析与规范化（从 0 实现）

## 1. 范围

**做**：把排期表里的时长写法批量解析成统一口径的规范化时长；歧义或无法解析的写法拒绝并给出固定原因码；同时产出逐行结果文件与一份自包含 HTML 报告。

**交付形态**：仓库根目录一个可 import 的模块兼命令行入口 `duration_normalize.py`：

```
python3 duration_normalize.py --input <输入文件> --out <结果文件> --report <报告文件>
```

`--out` 默认「输入文件名.out.txt」，`--report` 默认 `durations.html`；测试用标准库 `unittest` 编写。

**不做**：不做日历运算（闰年、节假日、时区、夏令时）；不解析日期、时间点与星期；不做句子理解与错别字纠正；不做并发、常驻与增量监听；不联网。

## 2. 口径与公式

- 预处理：整行 NFKC 归一、去首尾空白、ASCII 字母转小写。
- 数字：阿拉伯数字可带小数点（1.5）；中文数词支持 零一二三四五六七八九十百、「两」（=2）和「点」小数，取 0–999（如 九十、一百零五、一点五）；「半」= 0.5，写在单位前（半天、两个半小时）或单位后（一天半），每段至多一次。
- 单位与别名（按最长匹配识别）：

| 单位 | 别名 | 基准 |
| --- | --- | --- |
| 年 | 年、y、yr | 365 天 |
| 月 | 「个」+「月」（中间可夹「半」：3个月、一个半月、半个月）、mo | 30 天 |
| 周 | 周、星期、礼拜、w、wk | 7 天 |
| 天 | 天、日、自然日、d | 24 小时 |
| 小时 | 小时、时、h、hr | 60 分 |
| 分钟 | 分钟、分、m、min | 60 秒 |
| 秒 | 秒、s、sec | 1 秒 |
| 工作日 | 工作日、工日、wd | 不折算，1 个工作日 = 1wd |

- 换算基准固定写死：1 年 = 365 天、1 月 = 30 天、1 周 = 7 天、1 天（自然日）= 24 小时、1 小时 = 60 分、1 分 = 60 秒；工作日与自然日是两套体系，一条写法内不得混用，区间两端必须同体系，工作日不折算成秒。
- 复合写法：多段「数值+单位」相加，段间可用空格、逗号或「零」连接，顺序不限。
- 区间：两端用 `-`、`~`、`到`、`至` 之一连接，只允许一个连接符；一端可省略单位并继承另一端（3-5天、1.5-2个月）。
- 规范化输出：自然日体系折算为秒，写作「数字+s」（259200s）；工作日体系写作「数字+wd」（3wd）；四舍五入到小数点后 3 位（0.0005 进 0.001），去掉尾随 0；区间写作「下界~上界」（259200s~432000s）。
- 上限：单值按整条、区间按每端，最多 100 年当量（自然日体系 36500 天 = 3153600000 秒，工作日体系 36500wd），按舍入前的精确值判定。
- 往返一致性：规范化结果必须能再次解析出同一结果（幂等，区间两端同样适用）。

## 3. 判定顺序、记录与原因码

每条输入行按固定顺序判定，先命中先返回：归一化 → 空值 → 歧义 → 字符 → 语法 → 体系混用 → 上限 → 区间顺序。

记录固定四个字段：行号（从 1 起）、原文、状态（`OK`/`REJECT`）、结果（`OK` 给规范化值，`REJECT` 给原因码）；结果文件只用其中三列，原文只出现在报告里。

| 原因码 | 触发 | 报告里的固定说明 |
| --- | --- | --- |
| E_EMPTY | 空行、纯空白，或整行是 `-`、`—`、`无`、`null`、`n/a` | 空值：没有可解析的时长 |
| E_AMBIGUOUS_DATE | 命中日期形态：`YYYY-MM-DD`、数字+年+月+日/号、数字+月+日/号、单独的数字+号；其余写法不按日期处理 | 歧义：也可读作日期或日期范围，请改写成月数或天数 |
| E_AMBIGUOUS_MONTH | 「月」不在「个」或「个半」之后（3月、7月、3月到5月） | 歧义：裸「月」也可读作日历月份，请写成「x个月」或 xmo |
| E_AMBIGUOUS_WEEKDAY | 周、星期、礼拜 + 日名（周五、星期三、礼拜天） | 歧义：这是星期几，不是时长；写「x周」或 xw |
| E_CHAR | 白名单外的字符（`*`、`/`、`万` 等） | 有无法识别的字符或单位 |
| E_SYNTAX | 字符合法但不成写法：3.5.5天、1天2、-3天、3天到、2天半半、10-20 | 写法不合规：请按「数值+单位」改写 |
| E_CALENDAR | 一条写法内混用工作日与自然日，或区间两端体系不同 | 工作日与自然日不能混写 |
| E_LIMIT | 单端超过 100 年当量 | 超出上限：单端不超过 100 年当量 |
| E_ORDER | 区间下界大于上界 | 区间颠倒了：下界应不大于上界 |

白名单：数字 0-9、`.`、逗号、空格、`-`、`~`、「到」「至」、中文数词与「点」「个」「半」，以及上表别名包含的全部字符。

## 4. 输入输出与文件格式

- 输入：UTF-8 文本（LF 或 CRLF），每行一条，行数即记录数；空行也是记录，末尾的单个换行不产生记录。
- 结果文件：UTF-8 无 BOM、LF 行尾、末尾换行；每行「行号 TAB 状态 TAB 结果」，顺序与输入一致、行数相等，如「1 TAB OK TAB 259200s」。
- 报告：单个自包含 HTML（UTF-8 声明、内联样式、无脚本、无外链），至少含输入文件名、记录数、`OK`/`REJECT` 计数和逐行明细（行号、原文、状态、规范化结果、说明），拒绝行标红；`OK` 行的说明给出该行用到的换算基准（按「年、月、周、天、时、分」顺序用「；」连接，没有折算写「—」），拒绝行说明为「原因码：上表固定文案」。末尾给出「往返一致性自检」结论：把全部 `OK` 结果重新解析，报告通过数与总数。数值与结论必须由引擎计算，原文做 HTML 转义。
- 命令行：处理完成（含拒绝行）退出码 0；读不到输入或写不出结果时非 0。

## 5. 性能与验收口径

性能预算（单进程、单线程）：

- `samples/inputs/09_scale_100k.txt`（10 万行）：解析并写出结果 ≤ 10 秒，含报告 ≤ 20 秒，峰值内存 ≤ 256 MB。
- 单行解析与行长同阶，不得出现指数级回溯。

验收（全部满足）：

1. 对 `samples/inputs/*` 运行，结果与同名 `samples/expected/*` 逐行一致：行号、状态、数值格式、大小写、制表符、顺序全等。
2. 往返一致：结果文件里所有 `OK` 值再跑一遍，输出与第一次完全相同。
3. 可复现：同一批输入跑两遍，结果文件逐字节相同。
4. 报告内容与引擎输出一致、离线可打开。
5. 健壮性：单行内容不能让进程崩溃或漏记录，坏行只影响自身。
6. 只用标准库与 `unittest`，无第三方依赖、无构建步骤、无网络。

## 6. 样例说明

`samples/inputs` 与 `samples/expected` 同名成对，行序即输入行序。

| 文件 | 覆盖场景 |
| --- | --- |
| 01_common.txt | 常见写法：阿拉伯数字、中文数词、缩写与全称、小数、全角、首尾空白 |
| 02_composite.txt | 复合：多段相加、零/空格/逗号连接、半在单位前后、mo 与 d 混排 |
| 03_cross_month.txt | 跨月与月零头：一个半月、45 天、九十天、一点五个月、半年 |
| 04_range.txt | 区间：四种连接符、单位继承、跨单位、上下界颠倒、体系混用、无单位区间 |
| 05_workday.txt | 工作日：全称与 wd、半、与自然日混用、上限里外 |
| 06_ambiguous.txt | 歧义：日期范围、星期、裸「月」，对照「3个月」「3mo」 |
| 07_invalid.txt | 明显写错：双小数点、悬空数字、非法字符、负号、超限、中文数词错误 |
| 08_empty.txt | 空值占位符、0 值、四舍五入边界 |
| 09_scale_100k.txt | 10 万行规模批，含约 0.7% 拒绝行，用于性能与可复现验收 |

`samples/notes.md` 是触发这道题的现场记录。
